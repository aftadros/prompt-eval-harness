You set two timeouts because an LLM API call has two very different failure modes:

1. **The provider is unreachable** — you want to fail fast, so a short connect timeout catches the outage quickly.  
2. **The provider is reachable but generation is slow** — you may be willing to wait longer for a real answer to finish generating.  

A single timeout forces a compromise: if it’s too low, it can kill a valid response that was still being generated; if it’s too high, your request can hang for a long time when the provider is simply down [llm-api-from-php-in-production--two-timeouts].

For streaming calls, the “total” timeout changes meaning because the connection stays open while tokens arrive, so you may instead bound the idle gap between chunks rather than the whole call [llm-api-from-php-in-production--two-timeouts] [llm-cost-at-campus-scale--streaming-and-retries].
