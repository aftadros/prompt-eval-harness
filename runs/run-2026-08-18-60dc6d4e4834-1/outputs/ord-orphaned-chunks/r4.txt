An **orphaned chunk** is a fragment of a document that has been removed or rewritten but is still present in the retrieval index, so it can “win” search results for an unlucky query and be served as if it were current [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because orphaned chunks are a classic production failure mode: they cause users to act on stale or outdated guidance. If your indexing pipeline only adds new vectors and never deletes old ones, every one of those stale fragments can persist indefinitely [rag-over-internal-docs--freshness-is-an-indexing-problem]. That’s why the recommended approach is to delete a document’s old vectors in the same operation that writes its new ones, so retrieval doesn’t straddle two versions, and to run reconciliation jobs that remove chunks whose source documents no longer exist [rag-over-internal-docs--freshness-is-an-indexing-problem].
