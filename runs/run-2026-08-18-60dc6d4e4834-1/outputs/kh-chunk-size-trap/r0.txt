He doesn’t recommend one universal token size. He recommends chunking along the document’s own structure first—splitting on headings, keeping list items with their parent sections, and keeping tables with captions—and using a token limit only as a fallback when a section is genuinely too long. The 512-token window he mentions is an example of a fixed-window approach that can create bad seams, not his recommended size for internal docs [rag-over-internal-docs--chunking-decides-what-retrieval-can-find].
