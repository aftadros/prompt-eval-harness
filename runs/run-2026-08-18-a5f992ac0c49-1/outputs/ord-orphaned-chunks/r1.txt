An **orphaned chunk** is a fragment of a document that has been removed or rewritten but still remains in the index [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because orphaned chunks can keep winning retrieval for queries, causing the assistant to return stale guidance from an old version of a source [rag-over-internal-docs--freshness-is-an-indexing-problem]. If your indexing pipeline only adds new chunks and never deletes old ones, those stale fragments persist indefinitely [rag-over-internal-docs--freshness-is-an-indexing-problem]. That’s why the document recommends deleting old vectors when writing new ones and running a reconciliation job to remove chunks whose source documents no longer exist [rag-over-internal-docs--freshness-is-an-indexing-problem].
