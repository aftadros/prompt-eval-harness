An **orphaned chunk** is “a fragment of a document that was removed or rewritten months ago, still sitting in the index and winning retrieval for some unlucky query” [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because it can keep producing stale answers: if old chunks are not deleted when their source document changes or disappears, the assistant may retrieve guidance that no longer exists. The documents note that “a pipeline that only ever adds keeps every one of those forever,” so deletes matter as much as writes [rag-over-internal-docs--freshness-is-an-indexing-problem]. A reconciliation job should remove chunks whose source document no longer exists, because they can “creep in even when the pipeline behaves” [rag-over-internal-docs--freshness-is-an-indexing-problem].
