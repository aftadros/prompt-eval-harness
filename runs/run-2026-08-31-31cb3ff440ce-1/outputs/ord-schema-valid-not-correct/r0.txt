Yes. Structured outputs mainly guarantee shape, not correctness: the model can return a perfectly typed value that is still wrong [structured-outputs--what-it-didnt-fix]. You still need to validate whether the response is sane—for example, whether a category makes sense for the input and whether a tag is actually supported rather than just a plausible string that passed the schema [structured-outputs--what-it-didnt-free-form-string-field-in-a-schema-is-still-free-form-and-if-you-want-the-tag-to-be-a-real-tag-you-constrain-it-with-an-enum-or-you-check-it-against-your-own-list-after-the-fact].

Also, even when you attach a schema or use strict mode, decode the response defensively because models can still wrap JSON in prose or markdown fences [llm-json-in-php--send-the-schema][llm-json-in-php--then-decode-like-the-schema-might-not-have-held]. So validation shifts from “does it parse?” to “is this data semantically valid and safe for your app?”
