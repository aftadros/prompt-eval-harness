Yes—treat it as a **bounded content/semantic retry**, not a normal transport or schema retry.

Because the response is schema-valid but semantically wrong, the provider’s format constraints won’t fix it; your code has to detect that the enum value isn’t valid for that input [structured-outputs--retry-on-schema-mismatch]. Then retry once with the specific failure fed back into the prompt, e.g. “you returned X, which is not a valid value here; choose from this list” [structured-outputs--retry-on-schema-mismatch][llm-json-in-php--one-repair-attempt].

If that second answer is still wrong, stop and fall back instead of continuing to retry, because repeating the same request without new information usually just costs more for the same bad output [llm-json-in-php--one-repair-attempt][shipping-llm-features-safely--retries-that-dont-make-the-fire-bigger].
