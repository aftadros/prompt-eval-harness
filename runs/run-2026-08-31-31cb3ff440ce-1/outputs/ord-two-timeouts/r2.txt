You set two timeouts because an LLM API call has two very different failure modes: the provider may be unreachable, in which case you want to fail quickly, or it may be reachable but still generating slowly, in which case you’re willing to wait longer for a real answer [llm-api-from-php-in-production--two-timeouts].

So `connect_timeout` handles “can’t reach them” and fails fast, while the overall `timeout` bounds how long you’ll wait for generation to finish [llm-api-from-php-in-production--two-timeouts]. With streaming, the total-call timeout is less useful because the connection stays open as tokens arrive, so instead you bound the idle gap between chunks [llm-api-from-php-in-production--two-timeouts].
