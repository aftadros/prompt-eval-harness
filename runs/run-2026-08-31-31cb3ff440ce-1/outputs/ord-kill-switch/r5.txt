In practice, a kill switch for an AI feature is a coarse, boring configuration flag that can turn the feature off without requiring a deploy. It should be read on every request and not hidden behind a cache that would delay it by minutes. When turned off, the feature drops to its graceful-degradation or fallback path—for example, the assistant says the summarized answer is unavailable while retrieval and the rest of the app keep working [shipping-llm-features-safely--the-kill-switch].

The switch should be a known, tested mode rather than an error state, so it can be rehearsed before something goes wrong. Its purpose is to stop harm quickly—within seconds—if there’s a bad prompt change, unsafe provider output, a cost spike from a runaway loop, or a guardrail regression [shipping-llm-features-safely--the-kill-switch].
