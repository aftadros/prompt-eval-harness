In practice, a kill switch is a single coarse configuration flag that can turn the LLM feature off without requiring a deploy or build-and-release cycle [shipping-llm-features-safely--the-kill-switch]. It is read on every request and should not be delayed by caching, so it can take effect within seconds [shipping-llm-features-safely--the-kill-switch].

When switched off, the feature follows a prebuilt graceful-degradation path rather than entering an error state. For example, an assistant might say that the summarized answer is unavailable while retrieval and the rest of the application continue working normally [shipping-llm-features-safely--the-kill-switch]. The mode should be known and tested in advance so operators can rehearse using it during incidents such as a bad prompt change, unsafe provider output, a runaway cost loop, or a guardrail regression [shipping-llm-features-safely--the-kill-switch].
