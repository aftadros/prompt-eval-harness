An **orphaned chunk** is a fragment of a source document that has been removed or rewritten, but its old vectors are still in the index and can win retrieval for a query [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because they cause stale answers: outdated guidance can keep showing up even after the underlying document is gone or changed. A pipeline that only adds new chunks keeps those orphaned fragments forever, so old versions must be deleted—ideally in the same operation as writing replacements—and reconciliation jobs should remove chunks whose source document no longer exists [rag-over-internal-docs--freshness-is-an-indexing-problem].
