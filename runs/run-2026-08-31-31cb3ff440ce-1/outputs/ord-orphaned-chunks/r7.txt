An **orphaned chunk** is a fragment of a document that was removed or rewritten, but its vectors are still in the index and can win retrieval for an unlucky query [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because orphaned chunks let stale guidance survive after the source document has changed or disappeared. That can cause a RAG assistant to answer from outdated content, and users may act on that stale guidance before anyone notices [rag-over-internal-docs--freshness-is-an-indexing-problem]. A pipeline that only adds new vectors keeps these orphaned chunks forever, so you need deletes in the same transaction as writes, plus reconciliation jobs for chunks whose source document no longer exists [rag-over-internal-docs--freshness-is-an-indexing-problem].
