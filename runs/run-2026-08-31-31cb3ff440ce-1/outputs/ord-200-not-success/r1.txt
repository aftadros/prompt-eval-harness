A 200 status only means the request was processed at the HTTP transport level; it says nothing about whether the response *body* is usable. A model can return a clean 200 while the payload is **malformed** (e.g., invalid JSON), **off-topic**, or even **hostile**, and the HTTP layer will still file that under "success" [llm-api-from-php-in-production--a-200-is-not-success].

Because of this, the response should be treated as untrusted input from the moment it arrives: parse and validate any structured data against a schema before downstream code touches it, treat parse failures as retryable errors rather than crashes, and escape rendered text just like any other user-supplied string [llm-api-from-php-in-production--a-200-is-not-success].
