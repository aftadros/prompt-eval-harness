Putting an `enum` in the schema constrained the model to return only one of the allowed values, so it no longer produced off-list variations like `"Billing"`, `"billing issue"`, or `"this looks like a billing question to me."` That removed the need for the author’s lowercase-and-fuzzy-match step that collapsed those outputs into the intended buckets, and also deleted the test file covering that mapping logic [structured-outputs--schema-constrained-generation].
