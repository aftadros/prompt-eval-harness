Putting an `enum` in the schema deleted code because it removed the need to normalize free-text model output into fixed categories. Before, the model could return variations such as `"Billing"`, `"billing"`, `"billing issue"`, `"BILLING"`, or a full sentence, so there was a lowercase-and-fuzzy-match step to collapse them into one of four buckets. With the enum in the schema, the model is constrained to pick one of the allowed values directly, so that mapping step—and its test file—were no longer needed [structured-outputs--schema-constrained-generation].
