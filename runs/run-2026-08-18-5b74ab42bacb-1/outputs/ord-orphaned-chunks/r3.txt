An **orphaned chunk** is a fragment of a document that has been removed or rewritten, but remains in the RAG index—and can still win retrieval for some query [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because orphaned chunks are a classic production failure mode: they cause answers to rot by pulling stale guidance into results, potentially leading users to act on outdated information [rag-over-internal-docs--freshness-is-an-indexing-problem]. A pipeline that only adds new vectors keeps these fragments forever, so deletes matter as much as writes—old versions should be removed when new ones are indexed, and reconciliation jobs can catch chunks whose source document no longer exists [rag-over-internal-docs--freshness-is-an-indexing-problem].
