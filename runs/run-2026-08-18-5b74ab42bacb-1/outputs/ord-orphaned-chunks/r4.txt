An **orphaned chunk** is a fragment of a document that was removed or rewritten earlier, but its vectors are still in the index and can win retrieval for a query [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because orphaned chunks let an assistant keep serving stale guidance: a demo corpus may be fine, but real docs change—hours update, policies gain clauses, deprecated procedures disappear—and if the index keeps old versions, users can act on outdated answers [rag-over-internal-docs--freshness-is-an-indexing-problem]. A pipeline that only adds chunks preserves these orphans forever, so deletes matter as much as writes; ideally, when a document changes, its old vectors are removed in the same operation that writes the new ones, and reconciliation jobs can catch chunks whose source no longer exists [rag-over-internal-docs--freshness-is-an-indexing-problem].
