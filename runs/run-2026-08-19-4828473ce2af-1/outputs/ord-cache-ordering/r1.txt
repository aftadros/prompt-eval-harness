Order the prompt deliberately, putting **stable material first and volatile content last** so the reusable prefix stays intact [llm-cost-at-campus-scale--caching-the-stable-prefix].

A good order is:

1. **Static system prompt**  
2. **Tool definitions**  
3. **Retrieved context**  
4. **User’s question**  

The cached prefix can cover everything up to the first point where content changes, so keeping the early parts identical across requests lets the provider bill that repeated preamble at the lower cache rate instead of full input cost [llm-cost-at-campus-scale--caching-the-stable-prefix].

Also avoid inserting changing values—like timestamps or per-user tokens—near the top of the prompt. That can shrink the cacheable prefix to nothing and turn into a cost regression rather than an obvious failure [llm-cost-at-campus-scale--caching-the-stable-prefix].
