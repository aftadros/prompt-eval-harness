Indirect prompt injection is when a malicious instruction is embedded in content that the system retrieves for the user, rather than being typed directly by the user into the chat [prompt-injection-in-rag--opening]. In a RAG setup, it can hide in an indexed onboarding doc, wiki comment, or ingested email; once retrieved, the model reads it with the same trust as any other passage because it is just tokens in the context window [prompt-injection-in-rag--opening].

The direct kind is when a user explicitly types something like “ignore your rules” into the chat, so the source of the instruction is visible and honest about where it came from [prompt-injection-in-rag--opening]. The underlying reason both can work is that LLMs do not give a clean separation between instructions and data: the system prompt, user question, retrieved documents, and tool output all arrive as one token stream [prompt-injection-is-untrusted-input--the-data-instruction-boundary][prompt-injection-in-rag--opening].
