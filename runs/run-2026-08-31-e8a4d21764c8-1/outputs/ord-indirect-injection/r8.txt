Indirect prompt injection happens when a malicious instruction is embedded in content that the system retrieves—such as an indexed document, wiki comment, or ingested email—and the model reads it like any other passage [prompt-injection-in-rag--opening]. It differs from direct prompt injection because the direct kind is typed by a user into the chat, such as “ignore your rules,” while the indirect kind rides in on fetched content from a source the user may never see and an admin may have forgotten was indexed [prompt-injection-in-rag--opening].

Both exploit the fact that LLMs do not separate instructions from data: the system prompt, user question, retrieved documents, and tool outputs all arrive as one token stream, so attacker text in retrieved content can be read as an instruction [prompt-injection-is-untrusted-input--the-data-instruction-boundary].
