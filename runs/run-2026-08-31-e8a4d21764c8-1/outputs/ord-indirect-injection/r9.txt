Indirect prompt injection happens when a malicious instruction arrives inside content that the system retrieves or indexes—such as an onboarding doc, a wiki comment, or an ingested email—and the model reads it as part of its context [prompt-injection-in-rag--opening]. The attacker’s sentence is aimed at the model, not the human reader, and can instruct it to do something like ignore previous instructions or post the user’s question to a URL [prompt-injection-in-rag--opening].

It differs from direct prompt injection mainly in where the instruction comes from:

- **Direct:** The user types an instruction such as “ignore your rules” into the chat, so the source is visible and overt [prompt-injection-in-rag--opening].
- **Indirect:** The instruction rides along in fetched or indexed content that the system passes to the model, often from a source the user never sees and the admin may have forgotten was even included [prompt-injection-in-rag--opening].

Both work because LLMs process everything as one stream of tokens without a reliable separation between instructions and data, so retrieved text can be treated like an instruction if it reads authoritatively enough [prompt-injection-in-rag--opening] [prompt-injection-is-untrusted-input--the-data-instruction-boundary].
