An **orphaned chunk** is a fragment of a document that was removed or rewritten earlier but is still sitting in the index, so it can win retrieval for some query [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because they are a classic production failure mode: if your indexing pipeline only adds new chunks and never deletes old ones, stale fragments persist forever and can cause the assistant to return outdated or incorrect guidance [rag-over-internal-docs--freshness-is-an-indexing-problem]. That matters when real documentation changes—hours change, policies get amended, deprecated procedures should stop appearing—and you need retrieval to reflect the current version rather than an old one [rag-over-internal-docs--freshness-is-an-indexing-problem].
