An **orphaned chunk** is a fragment of a source document that was removed or rewritten long ago but is still present in the index. It can win retrieval for some unlucky query, causing the assistant to return stale or incorrect guidance [rag-over-internal-docs--freshness-is-an-indexing-problem].

You should care because it’s described as “the classic production failure” in RAG freshness: if your pipeline only adds new chunks and never deletes old ones, you keep orphaned versions forever. That means users can act on outdated information without anyone noticing until something goes wrong [rag-over-internal-docs--freshness-is-an-indexing-problem]. The fix is to delete old vectors when a document changes and run reconciliation jobs that remove chunks whose source no longer exists [rag-over-internal-docs--freshness-is-an-indexing-problem].
