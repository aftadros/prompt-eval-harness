Structured outputs guarantee the shape of the response, not that it is correct or sane: a model can produce perfectly valid JSON with a wrong `confidence`, an incorrect enum value, or an invented free-form string that still matches the schema [structured-outputs--what-it-didnt-fix]. So validation shifts from “does this parse?” to “is this semantically plausible and within your supported values?”

You should also keep defensive parsing. Even when you attach a JSON schema and enable strict mode if available, it raises the odds of a clean response but does not guarantee one; under load or on an older endpoint, the model may still wrap the JSON in prose or a markdown fence [llm-json-in-php]. Extract the JSON defensively and decode with errors promoted to exceptions so malformed output is catchable and retryable rather than fatal [llm-json-in-php].
