No—not directly. Prompt caching lowers the cost of reusing a stable prefix by billing that part at a cache rate rather than full input price, which cuts effective **input** cost [llm-cost-at-campus-scale--caching-the-stable-prefix]. Output tokens are priced separately and remain per-token output costs; the docs do not say caching changes output pricing or automatically reduces how many output tokens you generate [llm-cost-at-campus-scale--tokens-are-the-row-count].

So it can reduce your overall per-request cost, especially if the repeated prompt prefix is large, but it does not by itself bring down the cost of the model’s written answer.
