A 200 response only means the HTTP request succeeded; it doesn’t guarantee that the model’s body is actually useful or correct. The document explains that a model can return “a clean 200 with a body that's malformed, off-topic, or hostile,” so the response must be treated as untrusted input and validated—e.g., parsed and checked against an expected schema—before downstream code uses it [llm-api-from-php-in-production--a-200-is-not-success].
