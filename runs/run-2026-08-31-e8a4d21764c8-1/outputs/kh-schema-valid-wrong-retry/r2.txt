Yes—treat it as a **content/semantic retry**, not a structural schema retry. A response can be valid against your schema while still being wrong for your product; in that case you should run a semantic check and, if it fails, retry with the specific failure fed back to the model, e.g., “you returned value X, which is not valid here; choose from this list” [structured-outputs--retry-on-schema-mismatch].

Keep it bounded: give the model one repair attempt with the error attached, then fall back if the second answer is still bad rather than keep hammering the endpoint [llm-json-in-php--one-repair-attempt]. Also avoid retrying in a way that just repeats the same request unchanged, since a 200 response you can’t use is not a transient network failure and asking the same question the same way usually yields the same bad answer [shipping-llm-features-safely--retries-that-dont-make-the-fire-bigger].
