Yes—but make it a **bounded semantic/content retry**, not an ordinary schema-validation retry or a repeated identical request.

Schema-valid-but-wrong is real: the provider can enforce format, but it does not know what “valid” means for your product [structured-outputs--retry-on-schema-mismatch]. So if your code-level check finds the enum value wrong—for example, unsupported for that input or inconsistent with the expected category—retry once with the specific failure fed back into the prompt: “you returned X, which is not valid here; choose from this list” [structured-outputs--retry-on-schema-mismatch][llm-json-in-php--one-repair-attempt].

Do **not** just ask again unchanged. A 200 response with unusable output is not a default retry candidate, because asking the same question the same way often produces the same bad answer [shipping-llm-features-safely--retries-that-dont-make-the-fire-bigger].
