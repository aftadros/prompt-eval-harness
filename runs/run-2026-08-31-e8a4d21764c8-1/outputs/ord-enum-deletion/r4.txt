Putting an `enum` in the schema deleted code because it made the model’s output structurally conform to the allowed set of values instead of returning free-text variants. Previously, for classification, the model could return things like “Billing”, “billing issue”, or “this looks like a billing question to me,” so the author needed a lowercase-and-fuzzy-match step to collapse those into four buckets [structured-outputs--schema-constrained-generation]. With `enum` in the schema, there are exactly four allowed values and the model must pick one, so that mapping/normalization step—and its test file—were no longer needed [structured-outputs--schema-constrained-generation].
