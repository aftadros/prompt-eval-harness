Use structure-aware chunks rather than one fixed token size for internal documentation. The source recommends splitting on the document’s own headings and keeping related elements together—list items with their parents, tables with captions—and using a token limit only as a fallback when a section is genuinely too long [rag-over-internal-docs--chunking-decides-what-retrieval-can-find]. It also notes that fixed windows such as 512 tokens can work for uniform corpora but may create misleading seams in nonuniform internal docs, so the chunk size should be driven by document structure first and token limits second [rag-over-internal-docs--chunking-decides-what-retrieval-can-find].
