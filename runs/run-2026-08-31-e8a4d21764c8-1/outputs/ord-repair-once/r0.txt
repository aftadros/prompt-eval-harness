For malformed JSON from the model, give it **one repair attempt** after the initial failure — so **two total tries**. Send back the specific parse or validation error and ask again; if the second answer is still bad, stop retrying and fall back to whatever your feature does without the extraction [llm-json-in-php--one-repair-attempt].

This is different from retrying transient API failures such as connection errors, timeouts, 429s, or 5xx responses, which should have a hard cap rather than unlimited retries [llm-api-from-php-in-production--which-failures-to-retry].
